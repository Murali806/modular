                Keep each boundary honest.
                MAX and Mojo source is pinned at 610f7111836d9a950d45ba52ec9b3e0ed589fe3f. Every source link opens the complete original file. The external material informs the compiler concepts and visual treatment; MAX's own source determines its routes.
                

                Representation, toolchain and execution distinctions
                  

                • SOURCE: Python graph construction/finalization; compiler-owned cloning; MO/MAP/MOGG/MGP pass order; Mojo LIT/KGEN/POP/LLVM architecture; target backends; MEF serialization and init; runtime dependencies.
                  • 

                • ILLUSTRATION: paper files, the expression and IR previews, eligible fusion, binary bit patterns, conceptual MEF bins, SIMD bundle counts, allocation cells and tiny dispatch queues. These are not generated compiler dumps or a byte-accurate format view.
                  • 

                • BOUNDARY: device driver commands, hardware scheduling, transfer timing and execution motion. No MAX model, compiler toolchain or accelerator run is claimed by the animation.
                  • 

                • A dialect is an IR vocabulary within MLIR. Multiple dialects can coexist. Lowering to LLVM dialect and translating to LLVM IR are distinct transformations.
                  • 

                • Graph.output finalizes the symbolic output contract. Device-graph finalization within MGP and final runtime-call lowering are later compiler work.
                  • 

                • Assembly text can be emitted directly; relocatable objects can also be emitted directly. Disassembling an object/binary gives an inspection view without changing that binary.
                  • 

                • The NVIDIA source uses CUDA CompilationDevice for same-SM PTX-to-cubin compilation. A generic tutorial's ptxas command is not imposed as a mandatory MAX subprocess. Compilation targeting a GPU still needs toolchain support.
                  • 

                • Compile-time lifetime legality and runtime AsyncValue readiness solve different problems. A ready result does not universally imply a device-wide synchronization or an automatic host copy.
                  •

                1396    def output(self, *outputs: GraphOutputs) -> None:
1397        """Sets the output values of the graph and finalizes construction.
1398
1399        Call this once after building all ops. The graph can't be executed
1400        until ``output()`` has been called. Subsequent calls to
1401        :attr:`output_types` read back the types of the values passed here.
1402
1403        For example, build a graph that doubles its input and set the
1404        output:
1405
1406        .. code-block:: python
1407
1408            from max.dtype import DType
1409            from max.graph import DeviceRef, Graph, ops
1410            from max.graph.type import TensorType
1411
1412            input_type = TensorType(DType.float32, [4], DeviceRef.CPU())
1413
1414            with Graph("double", input_types=[input_type]) as graph:
1415                x = graph.inputs[0].tensor
1416                two = ops.constant(2.0, DType.float32, device=DeviceRef.CPU())
1417                graph.output(ops.elementwise.mul(x, two))
1418
1419        Pass one named tree, such as a dict of logits and hidden states, to
1420        name each output by its path in it; :attr:`output_tree` then returns
1421        the output types in that structure.
1422
1423        Args:
1424            outputs: The output values of the graph, or a single tree whose
1425                leaves they are. Each value may be a :class:`Value` or any
1426                :class:`~max.graph.TensorValueLike`.
1427        """
1428        root = (
1429            outputs[0]
1430            if len(outputs) == 1 and tree.is_node(outputs[0])
1431            else outputs
1432        )
1433        leaves, self._output_structure = tree.flatten(root)
1434        if any(isinstance(leaf, str) for leaf in leaves):
1435            raise TypeError(
1436                f"graph outputs {leaves} include a string, as when a named"
1437                " tree is unpacked into its keys: pass the tree itself, as"
1438                " graph.output(outputs)"
1439            )
1440        outputs = tuple(
1441            o if isinstance(o, Value) else TensorValue(o) for o in leaves
1442        )
1443        outputs = cast(tuple[Value[Any], ...], outputs)
1444        # mo.output doesn't support infer_type
1445        graph_body_args = self._graph_body.arguments
1446        output_values: list[Value[Any]] = list(outputs)
1447        if self._has_chain_input:
1448            output_values = self.device_chains.pack(output_values)
1449        mlir_values: list[_Value[Any]] = [v._mlir_value for v in output_values]
1450
1451        # We have a type mismatch now, these are MLIR types
1452        # Convert from max._core.Type to mlir.Type using CAPI bridge
1453        output_types = [

1456        ]

1462        )

1464        self._mlir_op.attributes["signature"] = mlir.TypeAttr.get(signature)
1465        self._mlir_op.attributes["functionType"] = mlir.TypeAttr.get(
1466            function_type
1467        )
1468

1471            mlir_values,
1472            _kgen.ParameterExprArrayAttr([]),
1473            attach_profile_scopes=False,
1474        )
1475

1477        # the engine for execution.

                152  /// Emits PTX via llc, then compiles it to a cubin via the CUDA compilation
153  /// device.
154  ErrorOr<BufferRef> emitObject(llvm::Module &module,
155                                EmitContext &ctx) const override {
156    // Compile to PTX first.
157    WriteableBufferRef codeBuf = WriteableBuffer::get();
158    if (ErrorOrSuccess err =
159            ctx.runLlc(module, *codeBuf, /*createObjectFile=*/false)) {
160      return Error(Twine(err.getError()) +
161                   ", llc failed to codegen LLVM IR to object code");
162    }
163    llvm::StringRef ptx(codeBuf->getBufferStart(), codeBuf->getBufferSize());
164
165    // A cubin must be assembled for the same arch as the `.target` directive of
166    // the PTX above. `ctx.tm` is the TargetMachine that emitted that PTX, and
167    // NVPTX takes `.target` from its subtarget, so that machine's CPU is the
168    // arch to assemble for. A CPU that is not an SM arch cannot name one.
169    llvm::StringRef targetArch = ctx.tm.getTargetCPU();
170    if (!targetArch.starts_with("sm_")) {
171      return Error(Twine("expected an NVIDIA SM target CPU (e.g. 'sm_90a') to "
172                         "compile PTX to a cubin, but got '") +
173                   targetArch + "'");
174    }
175
176    // Create CompilationDevice to compile from PTX to cubin.
177    ErrorOr<std::unique_ptr<Driver::CompilationDevice>> errCD =
178        Driver::CompilationDevice::create(Driver::Device::cudaAPI, targetArch);
179    if (errCD.isError()) {
180      return Error(
181          Twine(errCD.getError()) +
182          ", failed to create cuda compilation device to compile to cubin");
183    }
184
185#if MODULAR_LINUX
186    if (!llvm::sys::Process::GetEnv("MODULAR_NVPTX_COMPILER_PATH")) {
187      // We don't use NVPTXCompiler when MODULAR_NVPTX_COMPILER_PATH is set as a
188      // way to fallback to lower version of CUDA.
189      LLVM_DEBUG(llvm::dbgs()
190                 << "Using the NVPTXCompiler API to compile PTX to CUBIN.\n");
191      KGEN_DEBUG(0, {
192        llvm::dbgs()
193            << "Using the NVPTXCompiler API to compile PTX to CUBIN.\n";
194      });
195    }
196    KGEN_DEBUG(0, {
197      if (auto path =
198              llvm::sys::Process::GetEnv("MODULAR_NVPTX_COMPILER_PATH")) {
199        llvm::dbgs() << "MODULAR_NVPTX_COMPILER_PATH: " << path.value();
200      }
201    });
202#endif
203
204    return (*errCD)->compileFunction(ptx, ctx.options.getDebugLevelString(),
205                                     ctx.options.optimizationLevel);
206  }
