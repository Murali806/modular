The table shows semantic stages. MAX can stack Q/K/V and gate/up projections; RoPE, split and KV store are fused on this route. Paged attention consumes tiles without requiring the full score tensor in device memory.

Payload convention: table sizes use 2 bytes/value (BF16-compatible arithmetic); logits are FP32. Weights are untied, and SiLU applies to the gate. Hardware scheduling follows the MAX source links below. The saved checkpoint says FP16; this pinned architecture’s accepted encodings omit FP16. KV cache: what survives this pass?

Model lifetime · weights

E, 32 sets of decoder matrices/norms, untied W_head. Same weights for prefill and every decode.

Request lifetime · K′ and V

32 distinct layer slices. Retain each processed position’s rotated key and unrotated value. Length 0 → 512.

Current pass · activations

Q, residuals, attention results and FFN values change each call. Full scores/probabilities are a mathematical view of fused attention.

current token IDs → embedding → layer 0 → … → layer 31 → last row → norm → head
                                      │                                    │
                        K′, V → cache[layer, position]                     ↓
                            retained for later queries               sampled token ID
                            Q′ reads all causal keys                       │
                                                               NEXT forward creates its KV

Initial prefill: write positions 0…511 at all 32 layers. Used K+V = 2 × 32 × 512 × 32 × 128 × 2 = 268,435,456 bytes = 256 MiB. Each layer contributes 8 MiB. At page size P=128, four pages are exactly full.

Why cache? Reusing old K/V avoids projecting the whole prefix again. For current query i, allowed key positions satisfy j ≤ C+i. The new token attends to its own K/V too.

Physical pages, payload arithmetic and lifetime

Logical shape per request/layer: K,V each [L,32,128]. Ordinary physical backing: [physical_pages, 2, 32 layers, P, 32 KV heads, 128].

logical page = position // P          slot = position % P
physical page = lookup[request, logical page]
within-page element offset = ((((kv × 32 + layer) × P + slot) × 32 + head) × 128 + channel)
byte offset = (physical page × page_stride_elements + within-page offset) × dtype_bytes

Here kv=0 selects K, kv=1 selects V. CPU stride sentinel −1 means derive the packed stride; explicit strides can include padding. A logical sequence can occupy nonadjacent physical pages.

1.2 One block, with dimensions and equations

Let T be total active token rows across a ragged batch. For every layer l:

X_l [T,4096] ───────────────────────────┐
  → RMSNorm → QKV → RoPE/store → MHA → O projection
                                       ↓ add
H_l [T,4096] ───────────────────────────┐
  → RMSNorm → gate/up → SiLU(gate)·up → down
                                       ↓ add
X_(l+1) [T,4096]

RMSNorm(x) = x · rsqrt(mean(x²) + 1e-5) · weight, with the implementation’s casts and multiply_before_cast=False preserved. There is no mean subtraction, LayerNorm bias, dropout, cross-attention or MoE branch on this model route.

Stored projection weights use output-feature × input-feature shapes. Conceptually Q/K/V and O are [4096,4096]; gate/up are [11008,4096]; down is [4096,11008]. Execution can stack compatible projections and specialize layouts. This does not change the checkpoint’s parameter count.

1.4 The token boundary and output modes

Input token IDs are integer vocabulary indices. They are not bytes, characters or one-word-per-token labels. For [A0,A1,A2,B0,B1], the offsets [0,3,5] preserve request ownership without padding. A causal mask is local to each request and each absolute position.

The default last-token story uses one logits row per request. Other configured logits modes can return additional positions and offsets; the pipeline chooses next_token_logits when appropriate. The full transformer remains necessary to process active prompt rows even when only final-position logits are requested. Sampling and text decoding happen after the decoder’s logits output.
