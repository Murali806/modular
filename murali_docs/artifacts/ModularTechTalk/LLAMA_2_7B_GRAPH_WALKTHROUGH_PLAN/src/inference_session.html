Scope and illustration rules
  • SOURCE: the standard MAX model-worker route for meta-llama/Llama-2-7b-hf, using the built-in Graph API and an ordinary real-device session.
  • EXAMPLE: S1/M1 IDs, selected device combinations, thread settings, two weight-name tiles, token values and reference counts. Default CPU and multiple-device settings demonstrate the constructor; they do not certify that a given Llama configuration can execute on those targets.
  • BOUNDARY: animated driver/GPU submission and completion. No model inference, compilation, benchmark or GPU trace was run to produce these illustrations.
  • A native Engine::Context is owned by the session; the underlying MAX context, CPU runtime and device contexts can be shared. The diagrams do not assign private thread pools or physical GPUs to individual sessions.
  • Lesson 02 shows one ungrouped GraphSpec. Its stored-MEF example assumes a compatible matching entry. Graph tracing precedes this store lookup. Cold compile assumes no lower-level compiled-artifact cache hit.
  • Lesson 03 counts the illustrated decoder's setup once. It does not count all auxiliary graphs/models in MAX Serve. Output Buffer placement remains whatever the model returns.
  • Lesson 04 counts only pictured strong native-session references. Other references, outstanding work and shared resources can extend lifetimes.
