    Read the simulation contract and memory arithmetic

    All rates are teaching inputs. The model advances in deterministic 10 ms ticks. Each replica has an API tokenizer queue, exact N-slot IPC queue, CE set bounded by M, a batch ceiling, one conceptual GPU service timeline and token-counted output buffers.

    Generation produces its first token when prompt prefill finishes. Ordinary decode passes produce one token for each eligible decoder. Mixed passes sum linear prefill service, decode service and pass overhead. The model omits real kernel/bandwidth/cache interactions and cannot predict hardware performance.

    The lab reserves prompt plus effective output pages conservatively at GPU admission. Assigned pages grow with token progress. MAX uses its own allocation/preemption; the lab models the safe ownership invariant and retained pool, not that entire algorithm.

    
    
    N is exact here; real ZeroMQ HWM is approximate. M includes waiting and active prefill contexts. The example API waiting gate and fleet Add/Crash/Replace actions represent external/lab policy. Client count limits this teaching population to one unfinished request per client; unmet arrivals are reported as busy-client demand.
    
    
    The opening snapshot seeds contexts after tokenization/IPC. Future arrivals follow the normal stages. Changing inputs restarts the scenario. New replicas warm before receiving new work; existing requests stay with their selected replica. A crash fails unfinished streams instead of replaying tokens.
