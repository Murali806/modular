Quantization stores model weights with fewer bits. The goal is to reduce memory
traffic and storage while keeping the inference result close enough to the
full-precision model.

This page is a visual companion to the main
[Quantization guide](/develop/quantize/). Use that page for the canonical CLI
commands and API reference links.

:::note
The numeric animation below teaches the general idea with symmetric integer
quantization. It is not a byte-for-byte decoder for Q4_0, Q4_K, GPTQ, or another
specific checkpoint format.

## Read the animation

```text
FP32 weights
    |
    | choose scale and encoding
    v
small integer codes
    |
    | pack codes into uint8 storage
    v
quantized checkpoint weights
    |
    | ops.qmatmul(encoding, ..., activation, weight)
    v
output activation tensor
```

The quantized values are approximations. A lower bit width provides fewer
integer codes, so it usually saves more memory but can introduce more rounding
error.

## Standard and quantized linear layers

| Concern                  | Standard linear layer              | Quantized linear layer       |
|--------------------------|------------------------------------|------------------------------|
| Weight dtype             | `float32` or another floating type | `uint8` packed storage       |
| Weight shape in this API | `[in_dim, out_dim]`                | `[out_dim, in_dim]`          |
| Graph operation          | `x @ weight.T`                     | `ops.qmatmul(...)`           |
| Extra metadata           | None                               | `QuantizationEncoding`       |
| Bias                     | Usually floating point             | Usually still floating point |

```python
from max import nn
from max.dtype import DType
from max.graph import DeviceRef, Weight, ops
from max.graph.quantization import QuantizationEncoding


class QuantizedLinear(nn.Module):
    def __init__(self, in_dim, out_dim, encoding):
        super().__init__()
        self.weight = Weight(
            name="weight",
            dtype=DType.uint8,
            shape=[out_dim, in_dim],
            device=DeviceRef.CPU(),
            quantization_encoding=encoding,
        )
        self.bias = Weight(
            name="bias",
            dtype=DType.float32,
            shape=[out_dim],
            device=DeviceRef.CPU(),
        )

    def __call__(self, x):
        quantized_product = ops.qmatmul(
            self.weight.quantization_encoding,
            None,
            x,
            self.weight.to(x.device),
        )
        return quantized_product + self.bias.to(x.device)


layer = QuantizedLinear(64, 32, QuantizationEncoding.Q4_0)
```

```text
x: floating activation
        |
        v
ops.qmatmul(
    encoding=Q4_0,
    activation=x,
    packed_weight=uint8[out_dim, in_dim],
)
        |
        +-- interpret packed blocks using Q4_0 metadata
        +-- perform the encoding-aware matrix multiplication
        v
floating activation result
        |
        | add floating-point bias
        v
layer output
```

`qmatmul` handles the quantized representation during inference. Application
code does not need to unpack every weight into a Python tensor before running
the operation.

## Choose an encoding

| Encoding        | Weight precision | Typical reason to choose it                     |
|-----------------|-----------------:|-------------------------------------------------|
| `float32`       |          32 bits | Highest precision and largest memory footprint  |
| `bfloat16`      |          16 bits | Lower memory with a wide floating-point range   |
| `float8_e4m3fn` |           8 bits | FP8 checkpoints and supported FP8 operations    |
| `q6_k`          |           6 bits | More precision than four-bit K-family formats   |
| `q4_0`          |           4 bits | Compact, commonly used GGUF quantization        |
| `q4_k`          |           4 bits | K-family four-bit checkpoint representation     |
| `gptq`          |  Commonly 4 bits | Transformer-oriented post-training quantization |

The best format depends on the model, hardware, kernel support, memory budget,
and acceptable accuracy loss. A model may also mix encodings so sensitive
operations retain higher precision.

## Accuracy and performance trade-off

```text
more bits                                          fewer bits
   |                                                   |
   v                                                   v
more representable values                         fewer values
usually less rounding error                       usually more rounding error
more weight memory                                less weight memory
more memory bandwidth                             less memory bandwidth
```

Quantization can reduce weight traffic substantially, but speedup is not
guaranteed for every graph. Performance also depends on whether the target
hardware and MAX kernels have an efficient implementation for the selected
encoding.
